# Three.js AR — практика 5

Расширение предыдущей работы в ветке `practice-5-object-controls` того же репозитория. Обычное полноэкранное AR-приложение: сцена, компактная панель управления и кнопка запуска AR.

## Возможности

- Размещение независимых объектов на поверхности через WebXR hit-test.
- Выбор размещённого объекта из списка. После размещения новая копия выбирается автоматически.
- Замена выбранной модели: куб, кресло или сфера. Координаты, цвет, материал и угол сохраняются.
- Шесть цветов, поворот на 15° в обе стороны, автовращение с остановкой.
- Три PBR-покрытия: матовое, сатин и металл (`MeshStandardMaterial`, `roughness`, `metalness`). У кресла меняется обивка, ножки сохраняют материал дерева.
- Локальная HDRI Royal Esplanade (Poly Haven, CC0), загружаемая через `HDRLoader` и обрабатываемая `PMREMGenerator`. Карта назначается в `scene.environment` обеих сцен. Фон AR остаётся прозрачным.
- Студийная environment map на время загрузки и при ошибке HDRI.
- Сворачиваемая HTML-панель внутри WebXR DOM Overlay. `beforexrselect` предотвращает размещение при работе с кнопками, селекторами и панелью.

Модели создаются средствами Three.js; внешние glTF и CDN не требуются. Файл HDRI включён в репозиторий вместе с лицензией в `public/environments/`.

## Использование

1. В 3D-просмотре выберите модель, цвет и материал. Стрелки вращают объект, «Авто» включает вращение. Обзор сцены доступен мышью или пальцем.
2. На совместимом Android откройте приложение в Chrome по HTTPS и нажмите «Открыть AR».
3. Направьте камеру на пол или стол, плавно перемещайте телефон до появления зелёного маркера.
4. Нажмите «Разместить» либо коснитесь свободной части экрана.
5. Раскройте панель «Объект 1». Изменения применяются к выбранному объекту. Через поле «Выбран» можно переключиться на другую копию или настроить «Новый объект».
6. Следующее размещение копирует текущие настройки. Положение уже размещённых объектов не меняется.
7. Сверните панель, чтобы освободить обзор. Корзина удаляет все объекты, крестик завершает AR.

Для AR обязательны `hit-test`, `local-floor` и `dom-overlay`: без последнего браузер не сможет показать элементы управления. При отсутствии поддержки остаётся 3D-просмотр. Поиск плоскостей запускается после первого XR-кадра с трекингом; сохранены таймауты, повторный поиск и восстановление предыдущей работы.

## Структура

| Файл | Назначение |
| --- | --- |
| `src/main.js` | Создание сцен и рендерера, жизненный цикл XR, цикл кадров |
| `src/model-manager.js` | Класс `ModelManager`: создание, замена моделей и применение PBR-настроек |
| `src/models.js` | Геометрия моделей, контактная тень, освобождение ресурсов |
| `src/object-controller.js` | Класс `ObjectController`: выбор объекта, цвет, поворот и анимация |
| `src/ui-controller.js` | Класс `UIController`: HTML-события, отображение состояния, перенос панели в AR |
| `src/environment-lighting.js` | Класс `EnvironmentLighting`: HDRI, PMREM, резервное окружение |
| `src/placement.js` | Класс `HitTestPlacement`: маркер, неподвижные позы и очистка |
| `src/xr-runtime.js` | Асинхронная подготовка hit-test, таймауты и состояния поиска |

Поза hit-test хранится во внешней группе с `matrixAutoUpdate = false`. Поворот меняет `rotation.y` внутренней модели. Замена освобождает старые геометрию и материалы, сохраняя внешнюю группу; поэтому объект не перескакивает к маркеру или камере.

## Запуск и проверки

Node.js 22.12+:

```sh
npm ci
npm run dev
```

```sh
npm run check
npm test
npm run build
npm run preview
```

Для открытия на телефоне нужен HTTPS; HTTP-адрес компьютера в локальной сети не заменяет защищённый контекст. Папка сборки — `dist/`, пути ресурсов относительные.

20 модульных тестов проверяют сохранение позы, независимость копий, замену, освобождение ресурсов, вращение, трекинг, таймауты и восстановление поиска.

Для локальной эмуляции IWER в консоли браузера:

```js
await import('/tools/emulate-xr.js');
// Нажать «Открыть AR», дождаться поверхности и разместить объект.
xrEmulator.position.set(0.7, 1.6, 0.4);
__AR_LAB__.snapshot();
```

Эмулятор и диагностический объект доступны только при разработке и не входят в production-сборку. Эмуляция подтверждает поведение кода, но не проверяет физическую камеру, автофокус или ARCore. Требуется отдельная проверка на Android. Координаты сохраняются в текущей сессии; сохранение между сессиями, XR anchors и физические коллизии не реализованы. Контактная тень декоративная, HDRI не измеряет освещение реального помещения.

Публикация практики 5: https://batir8888.github.io/threejs-ar-hit-test/

Исходники практики 4 остаются в `main`. Практика 5 публикуется из ветки `practice-5-object-controls` ручным запуском workflow `Deploy to GitHub Pages` с выбором этой ветки. Автоматический запуск workflow по push по-прежнему настроен для `main`.
