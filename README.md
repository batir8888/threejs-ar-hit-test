# Плоскость — Three.js AR Hit Test

Практическая работа № 4: WebAR-приложение на **Three.js и WebXR**, которое находит поверхность через hit-test и позволяет разместить на ней виртуальный объект.

**Приложение:** [Открыть WebAR на GitHub Pages](https://batir8888.github.io/threejs-ar-hit-test/)

**Репозиторий:** [batir8888/threejs-ar-hit-test](https://github.com/batir8888/threejs-ar-hit-test)

## Использование

1. Откройте приложение в Chrome на Android на устройстве с поддержкой WebXR и ARCore.
2. Выберите куб или кресло. Куб имеет размер 30 × 30 × 30 см, кресло — примерно 56 × 64 × 52 см.
3. Нажмите **«Открыть AR»** и разрешите доступ к камере/AR.
4. Направьте камеру на хорошо освещённый пол или стол и плавно двигайте телефон. Зелёное кольцо отмечает точку пересечения луча с найденной плоскостью.
5. Коснитесь экрана или кнопки **«Разместить здесь»**. Можно добавить несколько независимых объектов.
6. Перемещайте телефон и обходите объекты: они сохраняют положение в текущей AR-сессии.
7. Корзина удаляет все размещённые объекты. Крестик завершает сессию и возвращает 3D-просмотр.

Если WebXR AR отсутствует, приложение показывает причину и оставляет доступным 3D-просмотр с поворотом мышью или пальцем. Этот просмотр не является AR. После завершения сессии объекты очищаются; сохранение между сессиями не реализовано.

## Соответствие заданию

| Требование | Реализация |
| --- | --- |
| Three.js и `immersive-ar` | `navigator.xr.requestSession('immersive-ar', ...)` в `src/main.js` |
| Корректная инициализация | Проверка HTTPS, WebGL, `isSessionSupported`; запуск с пользовательского клика; обработка ошибок и завершения |
| `local-floor` | Обязательная feature `local-floor`; `requestReferenceSpace('local-floor')`; то же пространство передаётся рендереру |
| `XRHitTestSource` | `requestReferenceSpace('viewer')`, затем `requestHitTestSource({ space: viewerSpace })` |
| Hit-test в каждом кадре | `frame.getHitTestResults(hitTestSource)` и `hit.getPose(renderer.xr.getReferenceSpace())` в `src/placement.js` |
| Маркер | Кольцо и центральная точка, их матрица обновляется из позы hit-test |
| Тап/клик | WebXR `select` через `renderer.xr.getController(...)` и кнопка DOM overlay |
| Фиксация объекта | Отдельная копия матрицы в группе сцены; объект не прикреплён к камере или маркеру |

`immersive-ar` — режим XRSession. `local-floor` — тип XRReferenceSpace, а не отдельный режим сессии.

Источник hit-test расположен в пространстве `viewer`, поэтому луч идёт вперёд от камеры. Результат преобразуется через `getPose(...)` в то же `local-floor`, которое использует Three.js. При размещении матрица **копируется один раз** в объект. Последующие кадры обновляют только маркер и камеру. Геометрия объектов начинается на высоте `y = 0` и стоит на опорной плоскости.

Если поверхность пропадает, маркер скрывается, а размещение по старой точке блокируется. При потере трекинга размещённые объекты временно скрываются без изменения их координат. Нажатия на элементы DOM overlay защищены событием `beforexrselect`, чтобы смена модели или очистка сцены не ставила дополнительный объект.

Фиксация действует в пределах текущего трекинга WebXR. XR anchors, сохранение между сессиями, физические коллизии и перекрытие объекта реальными предметами не реализованы. Тень декоративная, освещение виртуальное.

## Локальный запуск

Понадобится Node.js 22.12+ (проверено на 22.20).

```bash
npm ci
npm run dev
```

Откройте адрес, который выводит Vite. WebXR работает в защищённом контексте: HTTPS или localhost. HTTP-адрес компьютера в локальной сети при открытии с телефона не заменяет HTTPS.

```bash
npm run check
npm test
npm run build
npm run preview
```

Сборка находится в `dist/`. Three.js включён в сборку, его загрузка с CDN не требуется. Шрифт Manrope загружается через Google Fonts, при недоступности используется системный шрифт.

## Настольная WebXR-эмуляция

Можно использовать [Immersive Web Emulator](https://github.com/meta-quest/immersive-web-emulator) в режиме AR с поддержкой hit-test.

Для воспроизводимой локальной проверки также включён модуль на [IWER](https://github.com/meta-quest/immersive-web-emulation-runtime) 2.5.0 и `@iwer/sem` 2.5.0:

1. Запустите `npm run dev` и откройте localhost.
2. Выполните в консоли браузера:

   ```js
   await import('/tools/emulate-xr.js');
   ```

3. Нажмите «Открыть AR». Модуль эмулирует устройство и горизонтальный пол 20 × 20 м. Камера изначально расположена на высоте 1,6 м и направлена вниз на 45°.
4. Нажмите «Разместить здесь». Переместите камеру в консоли:

   ```js
   xrEmulator.position.set(0.7, 1.6, 0.4);
   __AR_LAB__.snapshot();
   ```

   Матрица камеры и маркер изменяются; матрица уже размещённого объекта остаётся прежней.

Для события WebXR `select` можно нажать и затем отпустить trigger эмулированного контроллера с интервалом между командами:

```js
xrEmulator.controllers.right.updateButtonValue('trigger', 1);
// Через один или несколько кадров:
xrEmulator.controllers.right.updateButtonValue('trigger', 0);
```

Скрытие/возврат сессии:

```js
xrEmulator.updateVisibilityState('visible-blurred');
xrEmulator.updateVisibilityState('visible');
```

`tools/emulate-xr.js` загружается только вручную на localhost и не входит в production-сборку. `__AR_LAB__` существует только в режиме разработки. Эмуляция не проверяет работу физической камеры, ARCore и точность трекинга конкретного телефона.

## Публикация

GitHub Actions в `.github/workflows/pages.yml` запускает проверку синтаксиса, тесты размещения, сборку и публикацию `dist/` на GitHub Pages при push в `main`. Относительный `base: './'` позволяет использовать сайт в подпапке репозитория. Pages даёт HTTPS, необходимый для WebXR.

## Структура

- `index.html` — страница, подсказки и DOM overlay.
- `src/main.js` — 3D-просмотр, управление XRSession, общий reference space и интерфейс.
- `src/placement.js` — hit-test, маркер, фиксация и очистка объектов.
- `src/models.js` — куб и кресло в метрах, декоративная тень, освобождение ресурсов.
- `src/style.css` — адаптивное оформление.
- `tests/placement.test.js` — проверки координат, отсутствия поверхности, трекинга и очистки.
- `tools/emulate-xr.js` — локальная WebXR-эмуляция для проверки.
